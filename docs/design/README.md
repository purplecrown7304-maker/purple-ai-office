로컬 첨부 파일의 실제 PNG 헤더 기준으로 세 원본은 모두 2880×1800이며 리사이즈·재인코딩 없이 보관한다. 채팅에 표시된 축소 미리보기 크기와 구별한다.

## 화면 기준

- 밝은 회색 배경, 큰 흰색 둥근 카드와 부드러운 그림자. GPT는 청록색, Claude는 주황색, 주요 행동·보드 강조는 파란색이다.
- 상단은 프로젝트명·오피스 제목, 데모 진행/제어, CEO 대기 상태로 구성한다.
- 데스크톱은 왼쪽의 큰 사무실/대화 카드와 오른쪽의 작업 보드/진행/예산·승인 카드로 나눈다.
- 사무실에는 두 에이전트와 각자의 모니터·책상·이름·상태 배지, 최신 메시지 말풍선, 두 책상 사이 메시지 전달 경로를 둔다.
- 작업 보드의 카드·열 개수, 진행 단계, 대화 목록·메시지 수, 비용·예산·검수 횟수는 DB 값으로 표시한다. 시안의 TASK-003, PR #83, 3/12, 11/20, $1.37 같은 예시를 고정하지 않는다.
- 시안의 ‘구현 Claude / 검수 GPT’는 역할 배정 예시다. 실제 화면은 tasks.lead_agent/reviewer_agent를 따르며 GPT/Claude 역할을 고정하지 않는다.
- WAITING_USER는 화면 상단의 CEO 상태와 승인 대기 알림에 항상 나타나게 하고 상세 승인 카드를 연결한다. 작은 화면에서도 대기 알림이 다른 카드 아래에만 숨지 않게 한다.
- 390px에서는 카드를 세로로 배치한다. 두 에이전트·책상과 전달 방향을 유지하고 말풍선/버튼이 잘리거나 페이지에 가로 넘침이 생기지 않게 한다. 1280px 이상은 시안의 두 열 구성을 따른다.

## DB → 애니메이션 계약

③에서 순수한 화면 상태 계산 함수를 두어 `tasks`, `task_events`, `agents`, `agent_messages`의 스냅샷과 새 DB 이벤트를 입력받는다. 필요하면 해당 메시지의 처리 상태/실행 기록을 조회하여 실제 처리 중인지 확인한다. React state나 타이머가 업무 상태·대화 대본을 대신하지 않는다.

| 표현 | DB 근거 | 동작 |
|---|---|---|
| 일하는 에이전트 | agents.current_task_id와 status, 해당 task의 실제 진행 상태·담당 역할 | 작업 중인 에이전트만 위아래로 부드럽게 들썩인다 |
| 구현 모니터 | IMPLEMENTING 또는 FIXING에서 실제 작업 중인 lead | 코드 줄이 타이핑되는 효과 |
| 분석 모니터 | ANALYZING에서 실제 분석 중인 agent | 모니터를 지나는 스캔선 |
| 검수 모니터 | CROSS_REVIEW에서 실제 검수 중인 reviewer | 모니터를 지나는 스캔선 |
| 질문·답변 모니터 | 해당 agent/task의 유효한 QUESTION/ANSWER 메시지와 처리 상태 또는 새 메시지 표시 구간 | 말줄임표 효과. 오래된 대화가 마지막 행이라는 이유만으로 무한히 ‘답변 중’으로 표시하지 않는다 |
| 메시지 꾸러미 | 새로 저장된 agent_messages.id, from_agent, to_agent, type | 발신 책상에서 수신 책상으로 꾸러미가 한 번 이동. 발신자 색상과 유형 라벨을 사용한다 |
| 말풍선·대화 피드 | 저장된 agent_messages.message 및 유형 | DB에 저장된 본문 표시. 질문·수정 요청 등 텍스트를 화면 대본으로 만들지 않는다 |
| 승인 대기 | WAITING_USER와 pause_reason | 해당 작업의 들썩임·타이핑·스캔·말줄임표를 멈추고 대기 배지를 표시한다. 새 호출/가짜 메시지 이동을 만들지 않는다 |

적용 우선순위는 **해당 작업의 정지/종료 상태 → 유효한 질문·답변 표시 → 수행 중인 업무 상태 → idle**다. 질문·답변이 다른 작업의 현재 동작을 덮어쓰지 않도록 current_task_id와 task_id를 함께 확인한다. DB에서 작업 중임을 확인할 수 없는 TESTING·PLANNED 등 상태에 임의로 타이핑 효과를 붙이지 않는다.

메시지 전달은 정확한 from/to ID로 방향을 정한다. CEO/system 발신·수신 메시지는 대화 피드와 승인 영역에 표시하며 두 에이전트 사이 전송인 것처럼 꾸미지 않는다. 새 agent 간 메시지 한 건에만 전달 효과를 연결하고, 여러 메시지는 안정적인 생성 순서로 처리한다.

CSS의 흔들림/타이핑/스캔/말줄임표 반복과 꾸러미 이동 시간은 표현용이다. 타이머가 task status, demo_step, message queue 상태, 비용을 변경하면 안 된다. 승인/재시작/일시정지 버튼도 서버 작업 결과가 DB에 반영된 후 그 상태를 보여준다.

### 재접속·중복·접근성

- 최초 스냅샷은 현재 상태를 표시하고 과거 메시지 전체를 새 전송처럼 재생하지 않는다.
- Realtime 중복 수신은 message/event ID로 제거한다. 동일 ID의 처리 상태 변경은 표시를 갱신하되 전송 꾸러미를 다시 만들지 않는다.
- 재접속·새로고침은 DB 스냅샷과 version을 기준으로 동기화한다. 연결이 끊기면 표시하고 가짜 진행을 만들지 않는다.
- `prefers-reduced-motion`에서는 반복·이동 애니메이션을 중지하고 상태 배지·방향·유형 텍스트로 같은 정보를 전달한다. 색상이나 움직임만으로 상태를 구분하지 않는다.

## Phase 1의 실제 기능 경계

시안의 ‘승인하고 병합’ 디자인은 승인 CTA의 시각 기준이다. **Phase 1에는 GitHub 병합 API가 없으므로 버튼은 ‘작업 승인’ 또는 ‘승인하고 완료’로 표기하고 검증된 WAITING_USER → DONE만 수행한다.** 실제 PR을 병합하거나 배포했다고 표시하지 않는다. 승인 사유가 예산 초과이면 최종 완료 승인과 구별한다.

‘배포’ 단계도 실제 배포 근거 없이 완료 표시하지 않는다. GitHub 자동화는 후속 Phase이고, 시안의 배포 단계는 후속 기능 안내 또는 미실행 상태로 남긴다. 데모의 ‘처음부터’는 감사·비용 이력을 삭제하지 않고 새 데모 실행/작업을 생성하는 방식으로 구현한다.

## ③ 검증 체크리스트

- [ ] 질문, 수정 요청, 대표 승인 대기 각각을 실제 DB fixture로 만들어 세 시안과 대조한다.
- [ ] 사용자 요청의 들썩임/타이핑/스캔선/말줄임표/꾸러미 이동을 각각 확인한다.
- [ ] GPT·Claude 역할을 바꿔도 구현자·검수자와 메시지 방향이 정확하다.
- [ ] 다른 브라우저에서 DB 상태/메시지를 바꾸면 현재 화면이 Realtime으로 갱신된다.
- [ ] 같은 메시지 ID 중복 전달, 재접속, 새로고침에서 과거 전송 재생이나 중복 꾸러미가 없다.
- [ ] WAITING_USER에서 에이전트 호출/작업 효과가 멈추고 상단 알림이 유지된다.
- [ ] 390px/1280px 이상에서 핵심 정보·버튼이 잘리지 않으며 reduced-motion도 동작한다.
- [ ] UI에 시안 예시 대본·작업 수·금액을 하드코딩하거나 GitHub 병합/배포 성공을 가장한 부분이 없다.
